Blueprint alignment

Section 3 asks for JSON-LD (at least as an option), resource IRIs usable as @id, GET for retrieval, and an OpenAPI/Swagger document.

bp_openapi_doc — Medium

  • Evidence: The documentation page has no parseable OpenAPI or Swagger document. Discovery stopped on this page: no linked .json / .yaml spec, no springdoc config, and no Swagger UI initializer.
  • Recommended next step: Publish an OpenAPI 3 document for the WDK Rest Service and link it from this page (a converted RAML file is enough). Point the link at the spec itself, not only at this HTML rendering.

bp_resource_iris — Medium

  • Evidence: The page states a verb-like path POST /users/{user-id}/favorites/query. The same path is the only verb-like path the analyzer recorded.
  • Recommended next step: Replace /favorites/query with a resource IRI, for example GET /users/{user-id}/favorites with the query in optional parameters, or POST /users/{user-id}/favorite-queries if the call creates a stored query.

Passed: bp_version_in_path. The page did not state a /v1/-style segment. The “(3.0)” in the title was not treated as a path version.

Not stated by the docs run (not a Blueprint failure of the HTML page): bp_jsonld_declared and bp_get_retrieval. The service-api page does not declare application/ld+json or @context. That absence is not, by itself, proof the API lacks JSON-LD.

The later live GETs are separate evidence. They did not return JSON-LD. See Samples. That observation does not change bp_jsonld_declared, which is about the document, and it does not raise confidence: no OpenAPI document was parsed.

Overall

Confidence stays low: the service-api page is a human rendering of a RAML API, not an OpenAPI document, so most Section 3 checks still cannot be scored from the spec. Live calls show the service is up and that retrieval of the root and record-type catalog uses GET and returns JSON, not JSON-LD. The highest-priority gap is still metadata encoding: the document does not declare JSON-LD, and GET https://plasmodb.org/plasmo/service/ answers Accept: application/ld+json with 406. Publish OpenAPI, and add JSON-LD at least on the record-type and dataset reads, before treating path cleanup as the first task.
